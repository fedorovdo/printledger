# Первичное создание каталога моделей из Excel

Catalog import предназначен только для массового создания отсутствующих моделей картриджей. Он отделен от инвентаризации склада: сначала создается каталог, затем тот же файл можно проверить и применить через обычный inventory workflow.

```text
Excel
→ Catalog Preview
→ проверка пользователем
→ Catalog Apply
→ Inventory Preview
→ Inventory Apply
```

Workflow доступен администратору в web-интерфейсе на странице `Картриджи`. Catalog import и складская инвентаризация остаются двумя отдельными операциями.

## Работа через интерфейс

1. Откройте страницу `Картриджи`.
2. Нажмите `Создать модели из Excel`.
3. Выберите файл `.xlsx` и выполните `Предпросмотр`.
4. Проверьте строки со статусами `Создать`, `Существует` и `Ошибка`, а также все предупреждения. Строка `Существует` не обновляет данные уже имеющейся модели.
5. Если ошибок нет, нажмите `Создать модели` и подтвердите создание отсутствующих моделей.
6. Закройте панель catalog import. Складские остатки на этом этапе не меняются.
7. Отдельно откройте `Инвентаризация Excel` и выберите тот же файл.
8. Выполните Preview инвентаризации и проверьте фактические остатки и рассчитанные корректировки.
9. Отдельно подтвердите Apply остатков.

Интерфейс не открывает инвентаризацию автоматически и не применяет складские изменения после создания моделей. Если каталог изменился между Preview и Apply, старый Preview блокируется и файл нужно проверить повторно.

## Формат файла

Используется лист `Инвентаризация`. Перед таблицей могут находиться информационные строки; строка заголовков ищется в первых 100 строках.

Для каталога читаются:

- `Производитель` → `vendor`;
- `Модель картриджа *` → `model_name`;
- `Артикул / SKU` → `purchase_sku`;
- `Тип *` → `cartridge_type`;
- `Мин. остаток` → `min_stock_level`;
- `Комментарий` → `notes`.

Колонки фактических остатков, общего количества и совместимых моделей принтеров не являются командами catalog import. Они не создают складские операции, модели принтеров или связи совместимости.

Поддерживаемые значения типа:

- `Тонер` или `toner`;
- `Чернила` или `ink`;
- `Другое` или `other`.

Регистр и повторяющиеся пробелы при сопоставлении не учитываются. Неизвестный тип является ошибкой строки.

`Мин. остаток` может быть пустым: тогда для новой модели записывается `0`. Иначе требуется целое число не меньше нуля.

`Комментарий` очищается от управляющих символов и ограничен 2000 символами. Более длинное значение блокирует строку и не возвращается целиком в Preview.

## Preview

```text
POST /api/cartridge-catalog/import/preview
Authorization: Bearer <admin token>
Content-Type: multipart/form-data
file=<xlsx file>
```

Preview имеет статусы:

- `create` — модель отсутствует и может быть создана;
- `existing` — точное нормализованное имя уже есть, запись не изменяется;
- `error` — строка блокирует весь Apply.

Preview является read-only и возвращает `snapshot_hash`. Он учитывает нормализованные данные строк, результат matching и текущее состояние каталога, влияющее на сопоставление и конфликты.

## Проверки конфликтов

- повторяющиеся нормализованные названия внутри XLSX блокируют все такие строки;
- одинаковый SKU у двух новых строк блокирует обе;
- SKU новой модели не может принадлежать другой модели в БД;
- если существующая модель найдена по имени, отличающиеся непустые `vendor` или `SKU` считаются конфликтом;
- несовпадающий тип существующей модели и строки Excel считается блокирующим конфликтом;
- если `vendor` или `SKU` в существующей модели пусты, заполненные значения Excel показываются как предупреждение, но не записываются;
- существующие модели никогда не обновляются этим workflow;
- fuzzy matching и автоматическое объединение строк не выполняются.

## Apply

```text
POST /api/cartridge-catalog/import/apply
Authorization: Bearer <admin token>
Content-Type: multipart/form-data
file=<тот же xlsx file>
snapshot_hash=<hash из Preview>
```

Apply повторно читает XLSX и текущий каталог под отдельной transaction-level PostgreSQL advisory lock. Если snapshot устарел, endpoint возвращает `409 Conflict`:

```text
Каталог изменился после предварительного просмотра. Выполните Preview повторно.
```

Если хотя бы одна строка имеет `status=error`, не создается ни одной модели. Все строки `create` добавляются одной атомарной транзакцией с одним `flush` и одним финальным `commit`; при любой ошибке выполняется rollback всей пачки.

Повторный Apply со старым hash после успешного создания возвращает `409`, потому что новый Preview уже считает созданные модели существующими.

## Что Apply не изменяет

Catalog Apply:

- не создает `CartridgeInventoryTransaction`;
- не применяет значения складских колонок;
- не изменяет существующие `CartridgeModel`;
- не изменяет установленные картриджи;
- не создает модели принтеров;
- не создает и не меняет совместимости;
- не обновляет metadata существующих моделей.

После создания отсутствующих моделей выполните обычный Preview инвентаризации. Новые модели начнут сопоставляться по имени и SKU, но inventory workflow по-прежнему сам модели не создает.

## Ограничения

- принимаются только `.xlsx`;
- максимальный размер файла — 5 MB;
- максимум 2000 непустых строк данных;
- требуется лист `Инвентаризация`;
- поддерживаются корректные XLSX без worksheet `<dimension>` metadata;
- миграция БД для этого workflow не требуется.
