# Резервное копирование PrintLedger

## Зачем нужен backup

Backup нужен, чтобы можно было восстановить базу PostgreSQL после ошибки, неудачного обновления, случайного удаления данных или сбоя сервера.

Рекомендуется делать backup:

- перед обновлением приложения;
- перед применением миграций;
- перед ручными изменениями в базе;
- ежедневно или еженедельно по расписанию на рабочем сервере.

## Где лежат файлы

Скрипты сохраняют файлы в папку:

```text
backups/
```

Имя файла выглядит так:

```text
printledger_backup_YYYY-MM-DD_HH-mm-ss.dump
```

Файлы backup не попадают в git.

## Совместимость версий PostgreSQL

Версия `pg_dump` и `pg_restore` в backend-контейнере должна совпадать с major-версией PostgreSQL server. Сейчас Docker Compose использует PostgreSQL 16 (`postgres:16-alpine`), поэтому backend устанавливает `postgresql-client-16`.

Если в будущем меняется образ `postgres` на другую major-версию, одновременно обновите версию PostgreSQL client в `apps/backend/Dockerfile`. Иначе backup/restore может падать из-за несовместимых параметров дампа.

## Backup через веб-интерфейс

После входа в систему откройте:

```text
http://localhost:3000/backup
```

На странице `Резервные копии` можно:

- посмотреть список backup-файлов;
- создать новый backup;
- скачать backup-файл.
- восстановить базу из выбранного backup.

Кнопка `Создать backup` запускает `pg_dump` из backend-контейнера и сохраняет файл в `backups/`.

## Скачивание backup

На странице `Резервные копии` нажмите `Скачать` напротив нужного файла. Скачивание выполняется через авторизованный запрос, поэтому сначала нужно войти в систему.

## Удаление backup через интерфейс

На странице `Резервные копии` нажмите `Удалить` напротив ненужного файла. Система попросит подтвердить удаление:

```text
Точно удалить резервную копию <filename>? Это действие нельзя отменить.
```

После подтверждения файл будет удален из папки `backups/` и исчезнет из списка. Удаление необратимо, поэтому не удаляйте все копии подряд. Рекомендуется всегда хранить хотя бы последнюю рабочую резервную копию.

## Восстановление через интерфейс

Восстановление через интерфейс доступно на странице:

```text
http://localhost:3000/backup
```

Нажмите `Восстановить` напротив нужного файла. Система покажет предупреждение и попросит ввести:

```text
RESTORE
```

Пока текст подтверждения не введен точно, кнопка подтверждения недоступна.

Перед восстановлением PrintLedger автоматически создает аварийный backup текущей базы:

```text
printledger_pre_restore_YYYY-MM-DD_HH-mm-ss.dump
```

Этот файл появится в папке `backups/` и в списке резервных копий.

После восстановления обновите страницу. Если сессия была сброшена или данные пользователей изменились, войдите заново.

## Restore через скрипт

Скрипты восстановления остаются аварийным/manual способом:

```powershell
.\scripts\restore_db.ps1 -BackupFile .\backups\printledger_backup_YYYY-MM-DD_HH-mm-ss.dump
```

или на Linux:

```bash
./scripts/restore_db.sh backups/printledger_backup_YYYY-MM-DD_HH-mm-ss.dump
```

## Backup на Windows

Из корня проекта выполните:

```powershell
.\scripts\backup_db.ps1
```

Скрипт создаст папку `backups`, если ее нет, выполнит `pg_dump` внутри контейнера `postgres` и выведет путь к созданному файлу.

Проверить, что файл создан:

```powershell
Get-ChildItem .\backups
```

## Restore на Windows

Восстановление перезаписывает текущую базу данных. Перед запуском убедитесь, что выбран правильный файл.

```powershell
.\scripts\restore_db.ps1 -BackupFile .\backups\printledger_backup_YYYY-MM-DD_HH-mm-ss.dump
```

Скрипт попросит ввести `YES`. После восстановления рекомендуется выполнить:

```powershell
docker compose exec backend alembic upgrade head
```

## Backup на Linux-сервере

Один раз дайте права на запуск:

```bash
chmod +x scripts/backup_db.sh scripts/restore_db.sh
```

Создать backup:

```bash
./scripts/backup_db.sh
```

Проверить файл:

```bash
ls -lh backups/
```

## Restore на Linux-сервере

Восстановление перезаписывает текущую базу данных.

```bash
./scripts/restore_db.sh backups/printledger_backup_YYYY-MM-DD_HH-mm-ss.dump
```

После восстановления:

```bash
docker compose exec backend alembic upgrade head
```

## Рекомендации

Для локальной разработки достаточно делать backup перед важными изменениями. Для рабочего сервера лучше настроить регулярный запуск скрипта: ежедневно, если данные меняются часто, или еженедельно для спокойного режима эксплуатации.
