# Excel-инвентаризация картриджей

Excel-инвентаризация помогает сравнить расчетный склад PrintLedger с физическим пересчетом картриджей. Phase 1 предоставляет только экспорт, загрузку, проверку и preview. База данных при preview не изменяется.

## Что считается складом

Склад учитывается отдельно по двум состояниям:

- `new` — новые картриджи на складе;
- `refilled` — заправленные картриджи на складе.

Картриджи, уже установленные в принтерах, хранятся отдельно. Значение «Установлено — справочно» не входит в физический остаток и не участвует в расчете delta.

## Экспорт

Скачать текущий файл можно через:

```text
GET /api/cartridge-inventory/export.xlsx
```

Файл содержит лист `Инвентаризация` и только активные модели картриджей. Технический столбец `ID модели` скрыт, но нужен для надежного обратного сопоставления.

Основные колонки:

- `ID модели`;
- `Производитель`;
- `Модель картриджа *`;
- `Артикул / SKU`;
- `Тип *`;
- `Сейчас — новый`;
- `Сейчас — заправленный`;
- `Новый — факт *`;
- `Заправленный — факт *`;
- `Установлено — справочно`;
- `Мин. остаток`;
- `Комментарий`.

Заполните обе колонки с пометкой «факт». Значения «Сейчас» и «Установлено» предназначены для сверки.

## Пусто не равно нулю

Пустая ячейка в `Новый — факт *` или `Заправленный — факт *` является ошибкой строки. Она никогда не преобразуется в ноль.

Явно введенное число `0` корректно и означает, что при физическом пересчете картриджей этого состояния на складе нет.

Разрешены только целые числа не меньше нуля. Отрицательные, дробные и текстовые значения возвращаются как ошибки preview.

## Сопоставление моделей

Система сопоставляет строку с существующей моделью в следующем порядке:

1. по техническому `ID модели`, если он заполнен;
2. по точному нормализованному названию модели без учета регистра и повторяющихся пробелов;
3. если одинаковых названий несколько, по производителю и/или SKU.

Если ID заполнен, fallback на название не выполняется. Несоответствие существующего ID указанным названию, производителю или SKU блокирует строку ошибкой `MODEL ID MISMATCH`.

Неизвестные модели получают ошибку `UNKNOWN MODEL`, неоднозначные — `AMBIGUOUS MODEL`. Новые модели автоматически не создаются. Одна модель не может встречаться в файле несколько раз: такие строки получают `DUPLICATE MODEL`.

## Preview

Проверить файл без изменения данных:

```text
POST /api/cartridge-inventory/import/preview
Content-Type: multipart/form-data
file=<xlsx file>
```

Preview возвращает текущие и фактические значения, delta, справочное количество установленных картриджей, ошибки, предупреждения и итоговую статистику.

Расчет выполняется так:

```text
delta_new = actual_new - current_new
delta_refilled = actual_refilled - current_refilled
```

Например, если сейчас числится 12 новых картриджей, а фактически найдено 10, preview покажет `delta_new = -2`.

`snapshot_hash` — SHA-256 от модели, фактических и текущих остатков всех корректных строк. В будущей Phase 2 он позволит убедиться, что склад не изменился между Preview и Apply.

## Ограничения Phase 1

- принимаются только `.xlsx` размером до 5 MB;
- требуется лист `Инвентаризация`;
- строка заголовков может находиться не в первой строке;
- обрабатывается не более 2000 непустых строк;
- полностью пустые строки игнорируются;
- preview не создает складские операции;
- preview не меняет остатки, модели, принтеры, локации или установленные картриджи;
- Apply endpoint пока отсутствует.

В будущей Phase 2 подтвержденные отличия будут оформляться через `correction_plus` и `correction_minus`, а не прямой записью остатка.
